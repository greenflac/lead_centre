## 1. Продукт в одном абзаце

Менеджер SORP открывает «входящие»: каждое обращение с сайта, из WhatsApp или с Property
Finder уже разобрано — что просят (офис, регистрация, визы, всё вместе), какая юрисдикция,
сколько людей, какой срок, на каком языке, и главное — приоритет с причинами. Рядом черновик
ответа на языке клиента с диапазоном цен и приглашением на встречу. Одна кнопка — и лид
с ответом уходит в HubSpot. Тот же движок раз в день просматривает свежие лицензии из
открытого реестра Дубая и кладёт в ту же очередь компании, которым по правилам скоро понадобятся
офис и визы. «Поиск и обработка трафика» — в одном окне, ответ за секунды вместо часов.

## 2. Допущения (ВЫБРАНО; поправьте, если не так)

1. **Входящие обращения для демо — синтетические**, 60–80 штук в стиле формы сайта и WhatsApp,
   RU и EN, с краевыми случаями (Т3): пустые, только «сколько стоит», на смеси языков,
   спам, крупная компания, solo-фрилансер. Сгенерированы Claude по шаблонам и отредактированы
   вручную; помечены `is_synthetic=true`. Реальных обращений SORP у нас нет — так и пишем.
2. **Dubai Pulse**: поля датасета (дата выдачи, вид деятельности, адрес, партнёры) и условия
   лицензии — НЕПРОВЕРЕНО до первого открытия файла. Час 0 дня 1: смотрим схему. Если нет даты
   выдачи — адаптер деградирует до Serper-новостей (backlog-план B).
3. **Модель**: `claude-opus-5`, adaptive thinking, effort `low` для извлечения/скоринга;
   `LLM_MODEL` в .env; в день 3 — сравнение с Sonnet 5 и Haiku 4.5. Бюджет на весь MVP < $10 (РАСЧЁТ).
4. **Хостинг API**: Vercel serverless (Python). Батч по Dubai Pulse гоняем локально или в
   GitHub Actions, если упрёмся в 10-секундный лимит.
5. **Supabase keep-alive**: GitHub Actions cron раз в 3 дня.
6. **Прайс демо** — `data/pricelist_demo.yaml`: мини-офис AED 40–50k/год (листинги Bayut/PF),
   пакеты setup/визы/бухгалтерия — диапазоны из ресерча 07 §1; в README пометка «демо, не прайс SORP».
7. **Loom** записывает пользователь по сценарию.

## 3. Definition of Done (конец дня 3) и стоп-условие (Ц9)

Сдано, если есть все шесть:
1. Живой URL: вкладка «Inbox» с обращениями, приоритет HIGH/MEDIUM/LOW, карточка с извлечёнными
   полями и причинами, черновик ответа, кнопки Approve (→ HubSpot) и Disagree (с причиной).
2. Форма «новое обращение» на том же URL: вставил текст → через несколько секунд карточка готова.
3. Вкладка «Discovered»: компании из Dubai Pulse с приоритетом и evidence (номер лицензии, дата).
4. Репо: README (EN) с архитектурой, trade-offs, eval (κ, confusion matrix, consistency), таблицей
   цена/латентность из реальных `usage`, «что не сделано и почему», один провал и починка.
5. `docs/onepager.md` для HR и Loom ≤ 4 мин по `docs/loom_script.md`.
6. `make eval` и `make run` печатают отчёт числами: `проверено N / нарушений M / не смогли K`,
   `synthetic S / real R`, `time-to-draft p50`.

**Стоп-условие.** Если к 18:00 дня 3 пункты 1–2 не работают end-to-end — фичи замораживаем,
README с честным статусом, Loom по тому, что работает, запись в HANDOFF.

## 4. Архитектура

```
 ВХОДЯЩИЕ                              ДВИЖОК (один для всех)                     ВЫХОД
 form/WhatsApp текст ─┐                                                          
 CSV обращений ───────┼─► intake ─► extract (Claude, JSON schema) ─► score (матрица A×B×C)
 Dubai Pulse delta ───┘                │                              │
                                       ▼                              ▼
                                 Supabase.leads               Supabase.scores ─► draft reply (RU/EN)
                                                                                     │
                                                              Next.js Inbox ◄────────┘
                                                                 │ Approve            │ Disagree
                                                                 ▼                    ▼
                                                              HubSpot           eval/disagreements.csv
 n8n (день 3): webhook формы → POST /leads → уведомление «HIGH: <имя>»
```

**Python-пакет `leadcentre/`**
- `intake/` — `inbound_text.py` (текст → RawLead), `inbound_csv.py`, `dubai_pulse.py`
  (CSV/API → RawLead с `license_no`, `issue_date`, `activity`, `address`, `partners`).
  Каждый адаптер возвращает список и счётчик `{real, synthetic, cached}`; `OFFLINE=1` — только кэш.
- `engine/extract.py` — `messages.parse()` → `LeadFacts`: `request_type[]` ∈ {office, setup,
  visa, accounting, bank, other}; `jurisdiction_hint`; `headcount`; `timeline_days`;
  `budget_hint`; `language`; `address_type_guess` (ось A) + `confidence`; `trigger_event` (ось B).
- `engine/rubric.py` — матрица A×B и модификаторы как данные (Е1); `engine/score.py` —
  детерминированный расчёт tier из `LeadFacts` + инварианты; модель предлагает tier, код
  проверяет (Е2).
- `engine/reply.py` — черновик 4–6 строк на языке клиента, с `pricelist_demo.yaml`,
  `observation_source` обязателен; `engine/lint.py` — стоп-фразы, лишние обещания цен.
- `crm/hubspot.py` — `CrmSink` + `NullSink`. `store/supabase.py`. `report.py`. `api.py` (FastAPI:
  `POST /leads`, `GET /leads`, `POST /leads/{id}/approve`, `POST /leads/{id}/disagree`,
  `POST /discover/run`, `GET /stats`).

**Eval `eval/`**: `labels.csv` (30 обращений, метки пользователя), `run_eval.py` (κ, confusion,
3 прогона consistency, негативные контроли: 3 спама/solo → LOW, 3 «переезжаем командой 8 человек,
нужен офис в TECOM в этом месяце» → HIGH), `disagreements.csv` пополняется из дашборда.

**Данные (Supabase)**: `leads(id, source ∈ {form, whatsapp, csv, dubai_pulse}, raw_text, facts jsonb,
language, is_synthetic, received_at)`; `scores(lead_id, model, tier, confidence, reasons, evidence,
prompt_version, usage jsonb, latency_ms, run_id)`; `replies(lead_id, language, body, lint_ok,
status ∈ {draft, approved, rejected}, decided_by, decided_at)`; `runs(...)`.

## 5. Рубрика v2 + ось C для входящих

Оси A (тип адреса) и B (событие) — как в рубрике v2 (адрес × событие; см. ниже). Для входящего
обращения добавляется **ось C — намерение и срочность**, извлечённая из текста:

| C | Признак | Эффект |
|---|---|---|
| C1 | Срок ≤ 30 дней или «уже в Дубае, ищем сейчас» | +1 ступень (макс. HIGH) |
| C2 | Просит пакет (регистрация + офис + визы) | +1 ступень |
| C3 | Только «сколько стоит» без деталей | tier не выше MEDIUM, ответ — уточняющие вопросы |
| C4 | Спам / не по теме / нет контакта | LOW, ответ не генерируется, флаг `needs_human=false` |
| C5 | Язык RU | +1 ступень (ЦА SORP), макс. HIGH |

Для Dubai Pulse-лидов ось C = C0 (нет обращения), приоритет только по A×B: свежая mainland-лицензия
на адресе бизнес-центра/«virtual Ejari» → MEDIUM; + вид деятельности из целевых сфер → HIGH-кандидат
для ручной проверки; лицензии, выданные 10–11 месяцев назад → «продление через 1–2 мес» → MEDIUM.

### Матрица A×B (из v2, без изменений)
| | B1 entering | B2 hiring | B3 renewal | B4 relocating | B5 funding | B0 none |
|---|---|---|---|---|---|---|
| A0 none | HIGH | HIGH | — | HIGH | MEDIUM | LOW |
| A1 flexi | HIGH | HIGH | MEDIUM | HIGH | MEDIUM | LOW |
| A2 serviced | — | MEDIUM | MEDIUM | MEDIUM | MEDIUM | LOW |
| A3 own | — | MEDIUM* | LOW | LOW | LOW | LOW |

\* только при ≥ 5 вакансий. Инварианты кода: A3+B0 → LOW; HIGH требует ≥ 1 evidence (для
входящих — цитата из обращения; для Dubai Pulse — номер лицензии); уверенность A < 0.5 →
не выше MEDIUM; C4 → LOW всегда. Нарушение → `invalid`, в отчёт как `нарушений M`.

## 10. Метрики MVP

| Метрика | Как | Цель |
|---|---|---|
| Согласие с разметкой | κ Коэна, 30 обращений | ≥ 0.6 |
| Стабильность | 3 прогона, % идентичных tier | ≥ 90% |
| Негативные контроли | 6 обращений | 6 из 6 |
| **Time-to-draft** | p50 от `POST /leads` до готового черновика, сек | печатается; ориентир < 15 с |
| Стоимость | $/лид из `usage` | печатается |
| HIGH с evidence | доля | 100% |
| Слоп/лишние обещания | нарушений линтера | 0 |
| Disagree-rate | доля Disagree на дашборде за демо | печатается, идёт в eval |

Конверсию в встречи и деньги не измеряем; в README — план пилота: 2 недели на реальном входящем
потоке SORP с параллельным ручным ответом, метрика — время до первого ответа и доля упущенных.

## 13. Δ после критики владельца (итерация 2, см. concept/CONCEPT_v4.md)

1. **Прайс:** `data/pricelist_demo.yaml` остаётся только для демо и помечен так в UI; в коде — путь
   `PRICELIST_PATH`, линтер `engine/lint.py` сверяет каждое число AED в черновике с диапазонами
   прайса; тест: мутация диапазона в прайсе красит тест (Т1).
2. **Discovered = watchlist:** вкладка без контактных полей (нет телефонов/email), только компания,
   лицензия, дата, причина. Кнопки «написать» нет.
3. **Eval честно:** в README метрика называется «стабильность движка на синтетике (κ автор↔модель)»,
   не «точность»; отдельная строка «точность на потоке SORP — после пилота, 30 реальных запросов,
   разметка менеджера».
4. **PII-минимизация:** `engine/extract.py` получает текст с вырезанными телефонами/email
   (регэксп до вызова); тест на негативный контроль (И5): телефон в тексте → не попадает в промпт.
5. **Авто-квитанция** — отдельный шаблон RU/EN без цен, генерируется движком, но в MVP не
   отправляется; показывается в карточке как опция.
6. **Стек:** демо на Vercel/Supabase; в репо — `docker-compose.yml` (Postgres + API + dashboard +
   n8n) для пилота; `HANDOVER.md` — черновик в день 3, полный — до пилота.
7. **Модель:** не-Covered (Opus 5 по умолчанию), чтобы не было обязательного 30-дневного хранения;
   регион Supabase — Frankfurt.
