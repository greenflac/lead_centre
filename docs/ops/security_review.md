## Находки

### 1. ВЫСОКАЯ. У API нет аутентификации, а дашборд проксирует его целиком наружу

**Где.** `web/next.config.mjs:15` — `{ source: "/api/backend/:path*", destination: "${target}/:path*" }`.
`leadcentre/api.py` — ни одной зависимости авторизации: `grep -niE 'auth|Depends|middleware|rate'`
по файлу даёт только `author`, `input_tokens`, `output_tokens` (ИЗМЕРЕНО).

**Почему это проблема.** Правило переписывает **любой** путь, поэтому посетитель публичной
страницы получает весь бэкенд на своём же origin, без CORS и без ключа:

- `POST /api/backend/leads` → `POST /leads` (`api.py:481`) — каждый вызов идёт в платную
  модель. Это открытый кран по деньгам на аккаунте Anthropic и по лимитам;
- `POST /api/backend/leads/{id}/approve` (`api.py:511`) — одобрение и отправка в CRM;
- `POST /api/backend/discover/run` (`api.py:583`) — обход внешнего реестра;
- `GET /api/backend/leads` (`api.py:487`) — весь корпус обращений с текстами;
- `POST /api/backend/leads/{id}/disagree` — запись в базу.

Формулировка в интерфейсе «Nothing is sent to the customer — a human presses the button»
(видно на скриншотах `01`, `02`, `02b`, `02c`, `02d`, `08`) верна по устройству кода — CRM
дёргается только из `approve`. Но «человек» здесь — кто угодно, у кого есть ссылка.
Само по себе это не утечка ключа: ключи живут на сервере. Это неограниченный доступ
к действиям, которые стоят денег и пишут в чужие системы.

**Что делать.** Публиковать дашборд в mock-режиме (`NEXT_PUBLIC_API_URL` пуст) — тогда
`rewrites()` возвращает `[]` и прокси не существует вовсе; это уже реализовано и это самый
дешёвый вариант для демо. Если нужен live — закрыть прокси токеном или basic-auth
на стороне Next и добавить ограничение частоты на `POST /leads` и `/discover/run`.

### 2. СРЕДНЯЯ. RLS включён, но политика отдаёт анониму на чтение все таблицы, включая тексты обращений

**Где.** `leadcentre/store/schema.sql:139-143` (включение RLS) и `:145-154` — цикл, который
на каждую из пяти таблиц вешает `create policy … for select to anon using (true)`.

**Почему это проблема.** Под «anon» подпадают `leads.raw_text` (текст обращения клиента),
`replies.body` (черновик ответа), `disagreements.reason` (внутренние оценки менеджера).
Комментарий рядом («публикуемому ключу — чтение») описывает намерение, но политика шире
намерения: сервер ходит секретным ключом, который RLS всё равно обходит, поэтому anon-чтение
здесь ничего не обслуживает — оно только расширяет поверхность. Publishable-ключа в
репозитории нет (проверено, см. вердикт), но такой ключ по своей природе предназначен для
браузера: как только к Supabase обратятся с фронта, чтение всей базы станет публичным.
Адрес проекта при этом уже опубликован — см. находку 3.

**Что делать.** Снять `anon`-политику с `leads`, `replies`, `scores`, `disagreements`;
оставить, если нужно, только `companies` (публичный реестр). Это правка `schema.sql`
плюс миграция; после неё стоит перепроверить advisors в проекте.

python -c "from leadcentre.crm import get_sink; print(get_sink().name)"                   -> null

### 6. СРЕДНЯЯ-НИЗКАЯ. Негативный контроль запрета сети печатает «работает» при любой ошибке

**Где.** `Makefile:21-24`.

**Почему это проблема.** Конструкция `python -c … 2>/dev/null && (провал) || echo "запрет сети работает"`
считает успехом любой ненулевой код возврата: сломанный импорт, опечатка в команде,
отсутствующий Python — всё это напечатает «запрет сети работает». Это Р1 в обход правила:
«не смогли проверить» сворачивается в «годно», причём именно у того прибора, который
доказывает, что тесты не ходят в сеть.

**Воспроизведено (И2), ИЗМЕРЕНО:**

```
$ PYTHONPATH=ci python -c "import definitely_not_a_module; import urllib.request as u; u.urlopen('https://api.gleif.org/', timeout=5)" 2>/dev/null \
    && echo "ПРОВАЛ" || echo "запрет сети работает"
запрет сети работает        <- напечатано, хотя причина — ImportError, а не запрет
```

**Сам запрет при этом настоящий** — проверено прямым прогоном с обоими контролями (И5):

```
$ PYTHONPATH=ci python -c "...urlopen('https://api.gleif.org/')"
BLOCKED BY: NetworkInTests тест пошёл в сеть — это запрещено: используйте OFFLINE=1 и кэш в data/
$ python -c "...urlopen('https://api.gleif.org/')"      # тот же вызов без запрета
сеть доступна без запрета: OK
```

**Что делать.** Проверять не код возврата, а исход: печатать имя исключения и требовать
`NetworkInTests`, иначе — третий исход «не смогли проверить», а не «работает».

Рядом: `ci/no_network.py` и `ci/sitecustomize.py` — побайтово одинаковые файлы, и на
`PYTHONPATH` работает только второй (Python сам импортирует `sitecustomize`). `no_network.py`
не подключён нигде (`git grep no_network` — 0 совпадений вне этого отчёта). Мёртвая копия
рядом с рабочей даёт ложную уверенность и разъедется при первой правке (Е1).
