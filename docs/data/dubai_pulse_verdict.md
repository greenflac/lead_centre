# Dubai Pulse: источник непригоден — замер 2026-09-09

Проверка сделана после того, как пользователь сообщил, что портал не открывается и у него.

## Что измерено

| Проверка | Результат |
|---|---|
| DNS `dubaipulse.gov.ae` | резолвится, `91.73.143.12` |
| TLS-рукопожатие с `www.dubaipulse.gov.ae:443` | проходит, сертификат `CN=*.dubaipulse.gov.ae` |
| `GET https://www.dubaipulse.gov.ae/` | обрыв, curl exit 35, при любом User-Agent, HTTP/1.1, TLS 1.2 |
| `GET http://www.dubaipulse.gov.ae/` (порт 80) | **503**, тело: `upstream connect error or disconnect/reset before headers … connection timeout` |
| `GET https://api.dubaipulse.gov.ae/` | 200, но это админка **webMethods Integration Server Administrator**; `/open`, `/api`, `/v1`, `/datasets` → 302 на вход |

503 с текстом про upstream отдаёт egress-шлюз: он сам не может достучаться до сервера портала.
То есть дело не в вайтлисте (домен в списке) и не в TLS, а в том, что сервер не отвечает.
Пользователь подтверждает: у него портал тоже не открывается. Вывод: источник недоступен,
а не «закрыт политикой».

## Чем это было в плане и что с этим не так

`docs/BLUEPRINT.md` §0 и §7 ставили Dubai Pulse несущим источником для вкладки «Найдено»
(outbound-адаптер). Ресерч 06 §5 честно помечал его `НЕПРОВЕРЕНО` — агент читал только
сниппеты, сам портал из среды не открывался, — и допущение 2 блюпринта тоже помечено.
**Пометки оказалось недостаточно.** По Ц10 внешнее имя доказывается командой до того, как
попадает в план; здесь на непроверенном источнике была построена целая функция MVP.
Правильный порядок был: открыть портал в час 0 дня 0, а не дня 1.

## Проверенные альтернативы (замер 2026-09-09, командой)

| Источник | Код | Годен? |
|---|---|---|
| `bayanat.ae` | 200 | содержимое рисуется JS; проверить содержимое не удалось — см. ниже |
| `dubaichambers.com` | 200 | справочник членов палаты, требует изучения |
| `difc.com/public-register` | 429 | rate limit, DIFC — только фризона DIFC |
| `dmcc.ae/members/directory` | 404 | по этому пути нет |
| `kaggle.com` | 200 | датасеты есть, скачивание требует аккаунта |
| `opendata.dubai.gov.ae`, `dsoa.ae` | нет соединения | — |

Браузер (Chromium + Playwright) в этой среде до сайтов не доходит: `ERR_CONNECTION_RESET`.
Негативный контроль — `pypi.org` в том же браузере падает так же, хотя curl его открывает.
Значит сломан браузерный доступ через прокси, а не сайт bayanat; **вывода о содержимом
bayanat из этого делать нельзя** (Р1: «не смогли проверить», а не «не годится»).

## Решение

Вкладка «Найдено» не должна зависеть от источника, который я не могу открыть.
Варианты вынесены пользователю; см. HANDOFF.
